# Repository Guidelines

## What this is

`github.com/spoolersh/pagedog`: a tiny open-source project powered by
[Spooler](https://docs.spooler.sh).

It handles pages and distributes them through a durable queue over disposable,
stateless workers.

Spooler facts (statuses, limits, guarantees) are never written here: read them
from the docs at the time and cite the page. The local server is the
`spoolersh/memspoolerd` image, in memory; <https://docs.spooler.sh/local> says
it is free to run for your own purposes, in development, tests and production
alike, and may not be provided to others or hosted as a service.

## Layout

Ben Johnson's [Standard Package
Layout](https://medium.com/@benbjohnson/standard-package-layout-7cdbc8391fc1),
in the shape the Go project gives a server at
<https://go.dev/doc/modules/layout>: commands in `cmd/`, everything else in
`internal/`.

- The root package, `pagedog`, is the domain: the types and interfaces the
  rest implements, standard library only.
- A package under `internal/` is named after the dependency it wraps
  (`spooler`, `claude`, `loki`, `prometheus`, `mcp`, `docker`) or the one thing
  it does (`ai`, `webhook`), and holds all of it: the Loki client and the
  agent's tools over Loki are both `internal/loki`. Nothing nests below it.
- No helper package: no `tools`, `util`, `common`. What two packages would
  share belongs to the domain or to the package it is about, or is written
  twice.
- `cmd/pagedog` is where the packages meet: it reads the configuration and
  wires them, and owns nothing else.

## Coding style

Standard library Go, `gofmt`, short lowercase file names. 

- When in doubt about a name or a shape, look for precedent: the standard
  library first (grep `GOROOT/src`, not memory), then the Uber and Google style
  guides. Report what was found, silence included, before recommending.
- Every exported symbol has a doc comment as Effective Go prescribes: a
  complete sentence starting with the name, in the current doc syntax (`[Name]`
  links, indented code). One package comment per package.
- Comments are concise: what a thing is or does in one line, and a non-obvious
  *why* only when the code cannot say it. A field comment exists only when it
  says what the name and the type do not.
- A field's zero value is the last line of its comment, its own paragraph,
  starting with "Zero": "Zero means [DefaultStopTimeout]." The word is always
  "zero". An optional field says so in its first sentence; a required one says
  what it names and nothing about being required.
- In a struct, a commented field is separated from the one before by a blank
  line; uncommented fields sit together. Settings before runtime state.
- Struct literals one field per line, even for one. `fmt.Errorf`, `t.Errorf`
  and log calls broken so the format and each argument sit on their own line.
- Assign a multi-line call on its own line, then `if err != nil`. An `if`
  header is always one line.
- Method case signals locking: an exported-style name synchronises itself, a
  lowercase one is a lock-held helper.
- Spooler's vocabulary is the docs': lease, spool, queue, settle, deliver.
  Never coin a word for a thing the docs name.
- Validate locally only what the server can never see.
- Secrets (API keys, auth tokens, leases, handles) never go on a command line,
  into a log or to a hook: environment only, redacted in traces.
- No global state, no logging library, no dependency that does not earn its
  place.

## Tracing

Observability is gtrace, not logging: a trace struct of `On*` callback fields
per component, named after the struct that holds it with the suffix `Trace`
(`Runtime.Trace` is a `RuntimeTrace`, never a bare `Trace`), a
`Logger<Name>Trace(*slog.Logger)` constructor that sets only its own fields,
and `*_trace_gtrace.go` files generated by `make generate_gtrace`,
never edited by hand. Hooks are verb-named, carry the error the operation
returns, are deferred at the top of the function they report, take typed codes
not strings, and never a secret.

## Testing

Table-driven with `testing`; test names are lowercase phrases. Case structs
hold scenario data only; fakes are assembled in the `t.Run` body. Assertions
actual first, then want: `t.Errorf("status: %d; want %d", act, exp)`. The value
under test is `act` and the expectation `exp`, never `got` or `want`. Specific
errors compare with `errors.Is` against an `expErr` field. Structs compare with
`github.com/google/go-cmp/cmp`: `opts` built once, `cmp.Equal(exp, act, opts)`
in the `if`, `cmp.Diff` only in the message, named "<thing>: %s". No helper
that wraps one call and fails on its error. In a test file the `Test*`
functions come first, `TestMain` included; stubs, fakes, fixtures and every
other helper type, func, const or var go below them, at the bottom.
`make test` and `make lint`, which is vet and govulncheck, clean before every
hand-off.

## Adding a component

A component is a source, a notifier, a model, a tool, a report store or a
worker runtime. Each is one package under `internal/`, the wiring in
`cmd/pagedog`, and the documentation; nothing else changes.

- **The package**, `internal/<system>`, the whole of the system in it, as
  Layout says. It implements the domain's interface for its kind: a source is
  a `webhook.IncidentSource`, served at `/webhook/<system>`; a notifier a
  `pagedog.Notifier`; a report store a `pagedog.ReportStore`; a model an
  `ai.Model`; a runtime a `runtime.Runtime`; a tool is one concrete `ai.Tool`
  per operation (`RangeQueryTool`, `LabelsTool`) over a `Source` interface
  that mirrors the client, no registry. Settings are exported fields with
  "Zero means" defaults; no `http.Client` field, a private or the default
  one; a trace struct as Tracing says. Tests beside it: `httptest` for an
  HTTP API, stub sources for tools.
- **The configuration**, `cmd/pagedog/config.go`: a `<system><Kind>Config`
  struct and a pointer field of it in the kind's one-of (`sourceConfig`,
  `notifierConfig`, `modelConfig`, `toolsConfig`, `reportConfig`,
  `runtimeConfig`). The field set is the choice; there is no `type:` key. A
  secret is a `pagedog_config.Secret`, a string that may be either a
  `pagedog_config.Value`. `validate` names what is required under the
  setting's path; `config_test.go` gets a parse case and an error case per
  rule.
- **The wiring**: the `switch` over the one-of in `server.go` for sources,
  notifiers and the runtime, in `worker.go` for the model, the tools and the
  report store; secrets read once through `unwrap` under the setting's path.
  A line in `banner.go` for the kind, a secret rendered by `source()`, never
  its value, and `banner_test.go` matching it.
- **The documentation**: a commented block in `pagedog.yaml` in the file's own
  style, its head says which; the line in README's "What's included"; the key
  in SKILL.md's configuration list and the wizard question it belongs to.
  `examples/` only when the demo should show it.
- `make test` and `make lint` clean.

## Editing files

Change project files only with the edit tool, one visible edit at a time, never
with a script (`sed -i`, perl, a heredoc into a source file). The owner edits
the same files concurrently. Scripts that only read are fine.

## Commits

Agents never commit, tag or push; the working tree is the hand-off. Commit
messages, when asked for, follow the standard library's "where: imperative
what": `ai: make MessageKind a uint`.

A release is a tag `vX.Y.Z` the owner pushes: the release workflow runs CI,
then goreleaser, which stamps the tag's version, the revision and the build
time into `internal/stamp`.
